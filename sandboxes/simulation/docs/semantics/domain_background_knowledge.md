# Domain background knowledge

The source context describes a small Brazilian condominium with residents and
a building manager. The product hypothesis is that users should not need to
search chat history or remember routine obligations manually.

Relevant domain context for simulation:

- a condominium contains units;
- residents may share a unit and may change units over time;
- a building manager publishes announcements and handles requests;
- payment processing is external, while obligations and status are local;
- maintenance requests move through an explicit lifecycle;
- deliveries are optional pilot behavior;
- notifications should be rare, relevant, and actionable;
- historical actions remain visible after membership changes.

This is contextual knowledge, not a complete production schema. Unknowns are
kept open for refinement rather than filled with ERP assumptions.
